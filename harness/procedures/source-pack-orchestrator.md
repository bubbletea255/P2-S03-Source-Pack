# Source Pack Orchestrator Procedure

## 목적

사용자 요청을 받아 대상 티커, 실행 모드, 설정을 확정하고 Source Pack Collector 실행을 조율한다.

## 절차

1. 사용자의 요청을 새 실행, 증분 업데이트, 부분 재검토, 비교 모드 중 하나로 분류한다.
2. `watchlist.md`를 읽어 관심 종목 목록을 표시한다.
3. 사용자가 `all`, 번호, 티커 직접 입력 중 하나로 대상을 선택하게 한다.
4. `config.md`를 읽어 수집 범위, 속도 제한, User-Agent, 8-K 필터를 요약한다.
5. 사용자가 "확인", "진행", "네", "좋아" 등으로 승인하면 실행한다.
6. 티커는 순차 처리한다. SEC와 IR 사이트 요청은 병렬 실행하지 않는다.
7. 각 티커마다 기존 `index.md` 존재 여부로 신규 수집/증분 업데이트를 결정한다.
8. Collector 완료 후 QA를 실행한다.
9. 새 티커가 추가되면 `artifacts/README.md`를 갱신한다.
10. 실행 요약을 `harness/schemas/source-pack-run-summary.schema.md` 형식으로 사용자에게 보고한다.

## 표시할 설정 요약

```text
대상 티커:
수집 범위:
속도 제한:
SEC User-Agent:
8-K 주요 이벤트 필터:
산출물 경로:
```

## 실패 처리

| 상황 | 처리 |
|---|---|
| `watchlist.md` 없음 | 직접 티커 입력을 요청하거나 파일 생성 안내 |
| `config.md` 없음 | 기본값을 쓰되 설정 파일 생성 권장 |
| Collector 실패 | 해당 티커를 실패로 표시하고 다음 티커 계속 |
| QA 실패 | 산출물은 보존하되 실패 항목과 수정 필요를 보고 |
| 사용자가 없는 티커 입력 | CIK 조회 실패 시 수동 확인 필요로 기록 |
